# Retry and Repair

An identical retry is allowed only for a classified transient failure and within the accepted attempt bound. Preserve the same plan, commit, lock, data, wrapper, evaluator, metrics, resources, and interpretation, and record a new Run.

A dependency or lock change, source commit or patch, data change, wrapper or entry-point semantic change, evaluator or metric change, resource-limit change, fidelity change, or evidence-interpretation change is material. Record the failed attempt, revise `KAOJU:METHOD-TRIAL-PLAN`, explain the difference, and obtain fresh review authorization before executing. Human review is the default. Explicit target-scoped prompt delegation permits the agent to review the revision only when it remains inside the delegated target and accepted pins. An out-of-bound change, ambiguous delegation, or protected credential, restricted-data, material-license, destructive-action, unexpected-resource, cost, or public-exposure boundary pauses for the actor.
